# Route-B Causal Audit

## Overall verdict

`HISTORICAL_GUIDANCE / NOT_A_CLEAN_REPRESENTATION_LEARNABILITY_ESTIMATE`.

The sprint genuinely trained on five different byte surfaces with matched trajectory order and
targets. It does not isolate representation learnability because the task labels are
metadata-solvable, the split seed is inert, later training mixes rejected data, semantic
content recurs across train/dev, the “verified” metric is vacuous with respect to mathematical
truth, truncation changes visible inputs by representation, and loss denominators differ.

## 8A — split seed: `INERT`

`stratified_split(tasks, ..., seed)` never reads `seed` (`prepare_matched_data.py:42–73`). It
sorts indices within domains and allocates deterministic round-robin prefixes. Seeds 0, 1 and
17 generate different world contents but identical split-index hashes. This is scientifically
material whenever prose treats the seed as randomized membership. `[VERIFIED_BY_CODE]`

Requested `600/48/48` cannot fit in 676 rows; actual output is `580/48/48`. IDs are disjoint.

## 8B — quality purity

| Subset | GOLD | SILVER | REJECT |
|---|---:|---:|---:|
| DEV | 48 | 0 | 0 |
| FRESH | 48 | 0 | 0 |
| Stage A first 224 train | 224 | 0 | 0 |
| Stage B first 576 train | 424 | 104 | 48 |
| available train 580 | 424 | 104 | 52 |

The generator deliberately emits a quality plan, but the training runner slices by position
without a quality filter. Thus the data generation is deliberate while the use as one pooled
learning curve is an unguarded design choice. It is materially confounded. `[VERIFIED_BY_SOURCE_DATA]`

## 8C — overlap

At the 224-example budget, DEV overlap is:

| Equality test | DEV matches | Interpretation |
|---|---:|---|
| trajectory/task ID | 0/48 | identifiers are disjoint |
| exact full action | 0/48 | generated IDs prevent equality |
| action excluding IDs | 19/48 | semantic answer/action templates recur |
| exact final answer | 21/48 | repeated label; not alone proof of leakage |
| exact normalized problem | 5/48 | actual same-problem recurrence |
| answer OR problem | 21/48 | headline recurrence statistic |
| operation | 48/48 | all DEV operation labels appeared in train |

The defensible statement is not “21 leaked problems.” Five are exact problem recurrences; the
remaining overlap is repeated answers/action structures and raises shortcut risk. Both matter,
but they are different. `[VERIFIED_BY_CODE]`

## 8D — “verified” metric

`score_prediction` parses JSON and then sets `verified=1` if the dictionary contains
`action_id`, `operation`, and `arguments`. The arbitrary wrong action
`{"action_id":"wrong","operation":"wrong","arguments":[]}` scores exact 0, schema 1,
verified 1. It does not call `NativeVerifier`, a domain oracle, or an optimality checker.
`[VERIFIED_BY_CODE]`

## 8E — representation implementation

The five arms resolve to five specialized classes:
`StructuredEnglishLanguage`, `CurrentHMLCompatibilityLanguage`, `SExpressionLanguage`,
`JsonAstLanguage`, and `CompactSymbolicLanguage`. Their `_encode_payload` methods are separate,
hard-coded codecs. Their genome attributes label the corresponding surfaces; the output is not
mechanically generated by perturbing every declared gene through the generic phenotype
interpreter. Therefore this is a legitimate comparison of five concrete codecs, not a causal
factorial study of genome genes. `[VERIFIED_BY_CODE]`

## 8F — token and loss comparability

The runner forms `prompt_ids + target_ids`, retains only the **last** 1,536 tokens, and computes
token-mean causal language-model loss. Different surfaces therefore have different token
counts, different left-context deletion, and different numbers of target/prompt tokens in the
mean. Stage-A recorded train tokens are 101,850 (English), 103,642 (HML), 130,507 (S-expression),
101,920 (JSON), and 94,080 (compact). Example count is matched; token exposure is not.

Cross-arm loss is not a common-scale estimator of representation learnability. Still usable:
exact target-object match on a no-truncation, group-disjoint test set; true verifier acceptance;
sample efficiency at matched examples **and** matched token/compute budgets; within-arm learning
curves; and wall-time/memory measurements when hardware/configuration are frozen.

## Minimum redesign

1. Replace World-v0 targets with opaque IDs and nontrivial multiple-action decisions.
2. Group-split by normalized problem/template family and freeze split hashes.
3. Train GOLD-only first; treat other quality tiers as preregistered interventions.
4. Use a real transition verifier and retain schema validity as a separate metric.
5. Guarantee no truncation or match visible token budgets; report both examples and tokens.
6. Use at least three split/training seeds and one phenotype interpreter for gene-level claims.
