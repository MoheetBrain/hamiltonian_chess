## 1. Executive state

Hamiltonian Arena has strong reproducibility infrastructure and a clear constitution separating
Σ, P, R, tokenizer, solver, controller, distribution, library, verifier and budget. It does not
yet have a valid payoff function for representation evolution. V1 and V3 were invalidated; V2,
V4 and V5 are instrument results; the historical matched sprint is guidance only. Phase 6 shows
a large descriptive solver effect but is invalid under its literal cache rule, and Qwen qualifies
only one mechanism versus the frozen requirement of two. `RSTAR_NOT_IDENTIFIED` remains.

The most valuable immediate assets are already local: 259,580 LeanDojo tactic transitions with
premises, 1,150 Lean runtime transitions (461 structurally eligible), 792 granular informal
steps, an official PRM800K clone and exact 500-row held-out MATH split. The next high-EV move is
not more architecture or another solver. It is to freeze Phase 6 honestly and construct two
shortcut-clean, real-state micro-environments—rewrite direction/site and premise selection—or
repair Route B if matched learning is the chosen route.

## 6. Route-B validity

Historical matched learning cannot be used as a clean representation-learnability estimate.
Stage A is GOLD-only but still uses a metadata-solvable task and has answer/problem recurrence.
Stage B adds 104 SILVER and 48 REJECT among 576 rows. The seed never affects allocation. The
five arms are concrete hard-coded codecs, not one-gene interventions. Per-token loss denominators
and visible left context differ; the last 1,536 tokens are kept. Its useful residue is engineering
timing, within-arm learning behavior, and a warning that concrete byte surfaces can affect
training. Redesign before spending another GPU hour.

## 7. World-v0 validity

It is a deterministic fixture, not a mathematical-reasoning benchmark. State→action rewrite,
domain→operation, unique legal action and first action are all exact. NEXT_ACTION projection does
remove legal actions when used, so the unique-action leak is projection-path dependent. The ID
and domain mappings remain sufficient in other views. Future tasks need opaque IDs, multiple
plausible actions and counterfactuals that preserve all metadata while changing the answer.

## 9. Reasoning operations

Existing traces support recurring semantic effects: introduce/localize, rewrite/substitute,
definition/theorem application, case/induction, witness/intermediate construction,
evaluate/bound, and discharge/close. Controller operations—retrieval, automation, tactic
selection, search—must stay separate. LeanDojo has 58,244 rewrite-family rows, 167,779 rows with
premises, 14,769 case/induction rows, 107,006 closures and 1,592 states with multiple goals.

## 11. Canonical-vNext

Proven immediate Lean gaps are multiple goal IDs, metavariable assignments/shared context,
dependent binding types, substitutions and typed import provenance. Typed implicit/instance
argument roles and premise refs are likely required. Universes and definitional equality are
backend-specific; keep the Lean kernel authoritative. Distinct-variable constraints are a future
Metamath requirement. E-graphs, MMT/OMDoc and universal tactic microsteps are deferred until a
concrete task demonstrates need.

## 12. Search / game-theory review

GOAL.md's strategy is sound. Population, Hall of Fame, Pareto diversity, surrogate and mutation
code exist, but no valid R payoff currently authorizes their use. Evolution before measurement
would optimize shortcut noise. Keep the verifier immutable and nonstrategic. Measure local
smoothness before local mutation. Do not use curriculum to hide causal failure, and do not force
representation evolution into zero-sum framing.

## 14. Three future strategies and decision tree

### A — if a valid run gets at least two qualified mechanisms

Freeze the instrument as a valid SCOUT, run the founder tournament at fixed cells, apply the
prespecified R-only gate, then run a bounded mutant campaign and landscape analysis. Matched
learning is allowed only if the R signal survives controls. This is **not** the current case.

### B — if exactly one mechanism qualifies

Do not declare V5 qualified and do not launch founders. Freeze the observation as evidence that
the solver can expose one capability, then either preregister a mechanism-specific R study with
a narrower claim or add a second independently qualified real-state mechanism under a new
protocol. This is the descriptive Qwen case, but the current Phase 6 is also invalid by cache
rule, so even the mechanism-specific experiment must be newly preregistered.

### C — if zero mechanisms qualify

Stop instrument iteration. Make repaired Route B primary: opaque/nontrivial tasks, group splits,
GOLD-only, true verifier, no truncation, multiple seeds and matched token/compute. Do not build
V6 merely to continue searching.

## 15. Recommended strategy

Use a disciplined hybrid of B and Route-B repair. First freeze/report the completed Qwen artifact
without rerunning it and classify Phase 6 invalid. Next spend a bounded CPU/Lean design sprint on
rewrite direction/site and premise selection from local LeanDojo/runtime states. If both pass
zero-model and solver positive-control gates, preregister a new instrument. In parallel only at
the design level, replace World-v0/Route-B leakage and verifier defects. Do not spend GPU or run
founders until one of those paths has a valid payoff.
